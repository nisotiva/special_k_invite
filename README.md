# Только для тебя

Кинематографичный персональный сайт-приглашение. React 19, TypeScript, Vite, Tailwind CSS 4 и Motion. Без собственного backend, аналитики и внешних шрифтов. Единственный внешний запрос — отправка в Discord Webhook после нажатия кнопки. Новых зависимостей при расширении не добавлено.

## Запуск

Нужен Node.js 22.22.2+ в ветке 22 (либо 24.15+ в ветке 24): это учитывает требования установленных тестовых зависимостей.

```sh
npm ci
npm run dev
```

```sh
npm run build
npm run preview
```

`npm test` проверяет Regalia, весь маршрут до календаря, неправильные ответы, навигацию календаря клавиатурой, восстановление сессии, все 96 временных значений, часовой пояс Europe/London, ошибки сети, запрет двойной отправки, точный Discord Embed и работу с opaque-ответом без чтения статуса/тела. Сетевые ответы в тестах подменены: реальные сообщения не отправляются. `npm run build` включает строгую проверку TypeScript. Отдельный lint в исходном проекте не настроен.

## Сценарий

Приветствие → Regalia → Цветы → Тысяча и одна ночь → Доверенность → Мюзиклы → «Но...» → Приглашение → Дата и время → Подтверждение сервиса.

Приветствие, `QuestionScene.tsx` и `CarWheelPicker.tsx` сохранены без изменений. Regalia всегда присутствует, варианты уникальные, барабаны запускаются один раз. После верного ответа кнопка ведёт в цветочный сад. Старый временный `SuccessScene.tsx` сохранён в исходниках, но заменён в маршруте новыми этапами.

Цветы — оригинальные SVG-иллюстрации: при правильном ответе те же четыре элемента пружинной layout-анимацией собираются в букет. Во дворце ночной фон перекрёстно сменяется отдельной рассветной композицией за 4 секунды; звёзды исчезают. Доверенность поднимается снизу и получает штамп. Мюзиклы растворяются до отдельной почти чёрной сцены с «Но...» и паузой примерно 1,8 секунды после появления слова. Приглашение раскрывается абзацами; затем доступен календарь.

Прогресс и ответы сохраняются в `sessionStorage` текущей вкладки. При перезагрузке уже решённая Regalia не крутится повторно, завершённые новые проверки восстанавливаются. Дата и время сохраняются как черновик. Незавершённая Regalia после перезагрузки запускает подбор заново; её существующая внутренняя механика не изменялась. Данные не синхронизируются между устройствами.

При `prefers-reduced-motion` барабаны сразу показывают ответ, движения отключаются. Смена сцен сохраняет управление клавиатурой, результаты сообщаются через live region. Анимации используют transform и opacity; размытие включённых в проект фонов подготовлено заранее в WebP.

## Архитектура

- `src/scenes/SceneManager.tsx` — единая последовательность, прогресс и переходы. Защита от двойного перехода.
- `SceneBackground.tsx` — наложение фонов, масштаб, overlay и тёплый свет.
- `SceneTransition.tsx` — появление контента.
- `WelcomeScene.tsx`, `QuestionScene.tsx` — существующие экраны без изменений.
- `CarWheelPicker.tsx` — отдельная автомобильная механика, общий менеджер о ней не знает.
- `themes.ts` — тип SceneTheme и конфигурации backgroundImage, overlayColor, overlayOpacity, blurAmount, textColor, accentColor, glassStyle, animationPreset.
- `src/story/FlowersScene.tsx`, `ArabianNightsScene.tsx`, `PowerOfAttorneyScene.tsx`, `MusicalsScene.tsx`, `ButScene.tsx`, `InvitationScene.tsx`, `DateTimeScene.tsx`, `ConfirmationScene.tsx` — новые самостоятельные этапы.
- `SceneElements.tsx` — общие карточки, появление текста и отложенные кнопки.
- `Calendar.tsx`, `dateUtils.ts` — календарь с понедельника, русская локализация, локальные даты и время с шагом 15 минут.
- `progress.ts` — безопасное чтение и сохранение сессии; `submitInvitation.ts` — POST и проверка ответа.
- `SceneErrorBoundary.tsx` — восстановление при ошибке загрузки. Календарь загружается отдельным JS-чанком с предварительной загрузкой во время приглашения.
- `src/story.css` — оформление новых сцен; прежний `src/style.css` не изменён.
- `src/performance.css` — облегчённая отрисовка фонов и стекла; `src/story/preload.ts` — кеш декодированных изображений и предзагрузка в свободное время браузера.

Чтобы добавить сцену: расширьте SceneId, добавьте её тему и компонент, затем подключите переход в SceneManager. Механика нового вопроса может быть любой. Для другой динамики появления расширьте animationPreset и SceneTransition.

## Фоны и использование

Все фоны основаны на оригинальных локальных SVG-композициях без сторонних изображений. Это атмосферные иллюстрации, а не фотографии. Для показа используются заранее размытые WebP, а SVG сохранены как редактируемые исходники. Можно свободно использовать и изменять в этом проекте.

| Этап | Исходник в `public/backgrounds` |
| --- | --- |
| Приветствие / Regalia | `evening.svg` / `garage.svg` — прежние фоны |
| Цветы | `garden.svg` |
| Тысяча и одна ночь | `palace-night.svg`, `palace-dawn.svg` |
| Доверенность | `study.svg` |
| Мюзиклы | `cinema.svg` |
| Драматическая пауза | `dark.svg` |
| Приглашение / подтверждение | `theatre.svg` |
| Дата и время | `theatre-close.svg` |

Четыре изображения цветов — `public/flowers/buttercup.svg`, `rose.svg`, `tulip.svg`, `peony.svg`.

Рядом с каждым SVG лежат `имя.webp` (1440 × 900) и `имя-mobile.webp` (768 × 480). Браузер выбирает размер через picture / source; оба набора сразу не загружаются. Для замены можно перезаписать эти файлы собственными оптимизированными изображениями. После правки SVG также пересоздайте соответствующие WebP.

Для другого источника укажите `backgroundImage` и, при необходимости, `mobileBackgroundImage` в `themes.ts`. `preblurred: true` означает, что изображение уже размыто; при `false`/отсутствии применяется `blurAmount`. Следующий фон предзагружается и декодируется по ходу истории. Нет бесконечных декоративных анимаций.

## Оптимизация плавности

- Убрана отрисовка SVG-фильтров на полноэкранных фонах: WebP уже содержит размытие. Мобильные изображения занимают примерно 0,7–7 KB каждое.
- Изображение и его статичное затемнение сменяются одним слоем через opacity / transform. Цвет полноэкранного overlay больше не пересчитывается на каждом кадре.
- Фон закреплён относительно viewport: рост формы и прокрутка длинной страницы не меняют его размер. Область отрисовки изолирована через contain.
- Перед сменой фон декодируется. Пока он не готов или если загрузка не удалась, остаётся прежний кадр. Это не блокирует переход текста и элементов управления. Предзагрузка переиспользует один Promise и выполняется в свободное время браузера; ошибочный ресурс можно запросить повторно.
- На телефоне снято дополнительное размытие с кнопок, барабанов и карточек; сохранены прозрачные заливки и границы. У документа и календаря — один облегчённый слой стекла. Из строк внутри документа убрано повторное размытие на всех экранах.
- Сокращено исчезновение старого текста до 280 ms, сохранено мягкое появление нового. Добавлена компенсация изменения позиции цветочной сцены при сборке букета.
- Убраны лишние тени-фильтры на движущихся цветах. GPU-подсказка барабанов снимается после остановки; сама механика Regalia не менялась.
- Форматтеры календаря переиспользуются вместо создания для каждой ячейки при каждом действии. Зависимости не добавлялись.

После оптимизации прошли 13 тестов и production-сборка. Дополнительно проверены готовность и отмена устаревших фоновых переходов, выбор мобильного WebP, отсутствие runtime blur у фона и мобильной кнопки, отсутствие горизонтального скролла. Численные замеры FPS на физических iPhone / Android не выполнялись.

## Discord Webhook

Предоставленный владельцем URL настроен локально в `.env.local`. Этот файл исключён из Git и ZIP исходников. Конфигурация читается из `VITE_DISCORD_WEBHOOK_URL` при запуске Vite / production build. Для другого окружения скопируйте `.env.example` в `.env.local`, замените WEBHOOK_ID и WEBHOOK_TOKEN на значения своего вебхука, затем перезапустите Vite. Реальное значение не нужно записывать в `src/config.ts`.

Для GitHub Pages: Settings → Secrets and variables → Actions → создайте Repository secret **VITE_DISCORD_WEBHOOK_URL** и вставьте URL вебхука. Можно использовать одноимённую Repository variable. Workflow передаёт `secrets.VITE_DISCORD_WEBHOOK_URL || vars.VITE_DISCORD_WEBHOOK_URL` только шагу `npm run build`. После настройки запустите workflow заново: окружение Vite встраивается при сборке.

Отправка выполняется только кнопкой «Воспользоваться полномочиями»: `fetch(webhook, { method: 'POST', mode: 'no-cors', body: FormData })`. Единственное поле FormData — `payload_json`, сериализованный Discord payload. Content-Type не задаётся вручную: браузер формирует multipart boundary. Нет прокси, backend, отправок при открытии страницы/изменении выбора и автоматических повторов.

Payload: username `Personal Invitation`; allowed_mentions `{ parse: [] }`; один Embed с заголовком `♡ Новое приглашение`, описанием `Karoline воспользовалась своими полномочиями и назначила совместный просмотр мюзикла!`, цветом `#D6A4BE`, footer `Полномочия реализованы`, timestamp текущего запроса в ISO 8601. Поля Embed: `Дата встречи` (DD.MM.YYYY), `Время встречи` (HH:mm), `Часовой пояс` (`Europe/London`). Дата и время переносятся из выбора без изменения; проверка прошлого и перехода на летнее время выполняется для Europe/London независимо от часового пояса устройства.

При отправке кнопка заблокирована и показывает «Отправляем приглашение...». При сетевой ошибке: «Не удалось отправить запрос. Попробуйте ещё раз». Выбор сохраняется, можно вручную повторить попытку. Ожидание ограничено 15 секундами. Завершившийся no-cors запрос возвращает opaque response: код **не читает** status, ok, headers или JSON и не подтверждает доставку. После завершения открывается прежняя финальная сцена с короткой пометкой об этой неопределённости. Состояние сохраняется как `delivery: 'unverified'`; перезагрузка ничего не отправляет повторно. Копирование даты и времени доступно как в календаре, так и в финальной сцене; если Clipboard API недоступен, появляется поле для ручного копирования.

### Как выполнить реальную тестовую отправку на GitHub Pages

1. Настройте secret/variable, опубликуйте текущую сборку через workflow и откройте опубликованный HTTPS URL.
2. Пройдите существующий сценарий. Выберите заведомо будущую тестовую дату и время по Europe/London.
3. Откройте DevTools → Network и нажмите «Воспользоваться полномочиями» **один раз**.
4. Проверьте один POST непосредственно к discord.com: FormData должен содержать только payload_json с выбранными значениями и пустым allowed_mentions.parse. Отправок до клика и повторных автоматических запросов быть не должно.
5. Проверьте соответствующий Discord-канал вручную: только наличие сообщения в канале подтверждает доставку. Финальная сцена сайта и завершившийся opaque-запрос этого не доказывают.
6. Перезагрузите финальную сцену: нового POST быть не должно. При неопределённом результате сначала посмотрите канал, чтобы не создать дубликат ручным повтором.

**Статус проверки:** 15 автоматических тестов и production-сборка прошли. Payload, FormData, no-cors, отсутствие чтения opaque response, защита от двойного клика, отсутствие отправок при монтировании/выборе времени, ручной повтор после ошибки, отсутствие повтора при восстановлении сессии и London/DST проверены с подменённым fetch. Проверка реальной отправки на опубликованном GitHub Pages ещё не выполнена: URL опубликованного сайта и репозиторий не предоставлены, локальная папка не является Git-репозиторием.

Документация: [Discord — Execute Webhook](https://github.com/discord/discord-api-docs/blob/main/developers/resources/webhook.mdx), [MDN — Fetch и opaque response](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch), [GitHub — переменные Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-variables).

## Проверка сценария локально

1. Выполните `npm ci`, затем `npm run dev -- --port 5180` и откройте адрес из терминала.
2. Пройдите Regalia; попробуйте неправильный ответ и убедитесь, что барабаны не вращаются заново.
3. В цветах нажмите на цветок, затем «Ни один. Все прекрасны». Во дворце выберите «Тысяча и одна ночь», в доверенности — пункт о встречах, свиданиях и допросах, в последнем вопросе — «Мюзиклы».
4. Дождитесь «Но...», прочитайте приглашение и нажмите «И что дальше?».
5. Проверьте календарь, переключение года, недоступные прошедшие дни, управление стрелками / PageUp / PageDown / Enter и все 96 временных значений. Сегодня доступны только будущие временные интервалы.
6. Для проверки ненастроенного окружения временно очистите `VITE_DISCORD_WEBHOOK_URL` и перезапустите Vite: должно появиться сообщение о неподключённой отправке и копирование. Реальная отправка выполняется только по описанным выше шагам и проверяется в Discord; в автоматических тестах fetch подменён.
7. Проверьте ширины 320–430 px, горизонтальную ориентацию, Tab / Enter / Space и системное reduced motion.

Чтобы начать заново в той же вкладке, выполните в консоли разработчика:

```js
sessionStorage.removeItem('personal-story:v2');
sessionStorage.removeItem('personal-story:date-draft');
location.reload();
```

## GitHub Pages

1. Создайте GitHub-репозиторий и загрузите **содержимое этой папки**, включая скрытую `.github`, в ветку `main`.
2. Settings → Pages → Build and deployment → Source → **GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` автоматически выполнит `npm ci`, `npm test`, `npm run build` и публикацию. Можно запустить вручную через Actions → Deploy to GitHub Pages → Run workflow.

Vite `base: './'` и `import.meta.env.BASE_URL` поддерживают и `username.github.io/repository/`, и корень личного домена. Клиентского роутера нет, настройка 404 не требуется. Для другой основной ветки обновите `branches` в workflow. Публикация в GitHub из этой сессии не выполнялась: workflow готов для вашего репозитория.
